## 1. Executive Summary & Problem Formulation

Modern software engineering environments expose developers to dense, heterogeneous terminal errors, stack traces, and deployment logs across containerized, serverless, and monorepo architectures. When developers paste these logs into general-purpose Large Language Models (LLMs), three failure modes regularly emerge:
1. **Unstructured & Overconfident Diagnoses**: Models output rambling explanations that conflate speculative root causes with established facts.
2. **Hallucinated or Destructive Action Prompts**: Models frequently suggest destructive terminal commands (e.g., recursive cache wipes, schema drops) without verifying rollback safety.
3. **Format Non-Compliance**: Unconstrained generation fails strict programmatic JSON schemas required for integration into developer toolchains (IDE extensions, CI/CD triage agents).

**OOPSIE** (Open-source Operational Problem Solving & Inference Engine) investigates whether domain-adapted open-weights language models can reliably parse unstructured errors into strictly structured, cautious diagnostic envelopes with actionable repair prompts and explicit safety warnings.

## 2. System Architecture & Operating Boundaries

```
[Developer Terminal / CI Log] 
             │
             ▼
  ┌───────────────────────┐
  │ Best-Effort Redaction │ (Regex detection of known secrets & credentials)
  └──────────┬────────────┘
             ▼
  ┌───────────────────────┐
  │ Inference Service     │ (FastAPI with non-blocking concurrency semaphore)
  │ (Gemma 4 12B + QLoRA) │
  └──────────┬────────────┘
             ▼
  ┌───────────────────────┐
  │ Pydantic Validator    │ (Strict 10-key schema & category enum verification)
  └──────────┬────────────┘
             │
             ├──► [Valid 200]: Advisory Diagnostic Envelope
             └──► [Schema Error 422]: Quarantined / Strict Rejection
```

### Advisory-Only Safeguards
- **Strictly Advisory**: The system provides explanations, clarification questions, and copy-ready prompts for human review. It does not automatically edit source code, execute shell commands, or trigger deployments.
- **Privacy & Logging**: Secret redaction uses heuristic regex pattern matching. **Secret removal is best-effort and not guaranteed**; users must review submissions.
- **Structural vs. Semantic Boundaries**: Automated schema validation enforces strict JSON key presence and enum types. It does not guarantee diagnostic accuracy, semantic safety, or code fix efficacy.

### Key Analytical Takeaways
1. **Base System Parsing**: The base conditions (A and C) achieved 0/40 raw JSON parse validity under strict zero-tolerance parsing, emitting conversational preambles, introductory prose, or markdown code fences (` ```json `).
2. **Adapter Structural Bias**: Across all 40 held-out cases, the adapted model began with valid JSON syntax; 38/40 (95.0%) under Condition B and 39/40 (97.5%) under Condition D completed as strictly valid schema reports.
3. **Paired Transition Advantage**: In the primary paired comparison (Condition A vs. Condition B), 38/40 cases (95.0%) transitioned from Base-Fail to Adapter-Pass ($A- B+$), 0/40 exhibited Base-Only pass ($A+ B-$), and 2/40 failed under both ($A- B-$).
4. **Diagnostic Category Agreement**: On strictly parseable completions, Condition B matched reference categories in 28/38 cases (73.7%) and Condition D matched in 27/39 cases (69.2%) across 9 distinct categories.
5. **Absence of Generation Failures**: Across all 160 benchmark forward passes on a Kaggle Tesla T4 GPU (5.03 hours total execution), zero generation crashes occurred, zero delimiter loops were detected, and zero output-budget terminations were triggered.
6. **Integration Latency Note**: In real-GPU in-process service testing on a Tesla T4 GPU, non-blocking health check latency was measured at **3.2 ms** during background model generation; model loading took 225.29s (5.30 GB allocated VRAM).

The 40-record held-out benchmark ([`evaluation/benchmark.jsonl`](file:///c:/Users/onyxe/Desktop/OOPSIE/evaluation/benchmark.jsonl)) was executed end-to-end on Kaggle across all four frozen conditions (160 total passes). - **Primary Comparison (A vs. B)**: Adapter demonstrated a +95.0 percentage point advantage in strict schema compliance (exact McNemar binomial test $p \approx 7.28 \times 10^{-12}$; Edwards continuity-corrected $\chi^2 = 36.03, p \approx 1.95 \times 10^{-9}$; 38/40 $A- B+$, 0/40 $A+ B-$).
- **Secondary Comparison (B vs. D)**: Removing the raw JSON schema text in Condition D improved mean latency by 14.54s (-12.7%) while maintaining 97.5% schema compliance (40/40 raw JSON valid).
- **Condition D Metric Resolution**: All 40 cases in Condition D yielded parseable JSON (40/40), with 28/40 matching reference categories (70.0%). Exactly one case (`bench-npm-03`) omitted `matched_recipes: []`, yielding 27/39 (69.2%) agreement among schema-valid outputs.
- **Remaining Step**: Blinded human technical review of the 40 benchmark cases across the 4 systems using 8 partitioned batches (`docs/research/human_review/`) and the frozen rubric. The unblinding key remains isolated in `unblinded_review_key.json`.
